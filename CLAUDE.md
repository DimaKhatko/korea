# CLAUDE.md — PointCamp Korea 2027 landing

## Repo facts
- Landing: spring 2027 teen trip to South Korea (Seoul – Gyeongju – Busan – Seoul), one group, 21–30 March 2027.
- Repo: `korea` (cloned from `DimaKhatko/japan` without history) · Stack: TanStack Start (Lovable config) + React + Tailwind v4 + Bun.
- LANDING = `korea`.
- Build output: `dist/client`.
- Firebase: project `pointcamp-a1a24`, target `korea` → site `pointcamp-korea` · domain `korea.pointcamp.com.ua`. There is deliberately no `japan` target in this repo: a deploy from here must never reach the Japan site.
- Default branch: `main`.
- Lockfile: `bun.lock` is the only lockfile.
- Config wrapper: `@lovable.dev/vite-tanstack-config` 2.x — uses `nitro: false`; `bun run build` prerenders `/` with its full content to `dist/client/index.html` (static prerender, not the SPA shell).
- Toolchain: Vite 8.1.5; TanStack Router 1.170.18 / Start 1.168.32 / router-plugin 1.168.23; wrapper `^2.20.0`; `nitro` 3.0.260603-beta (dev); `overrides.rolldown` 1.2.1.

## Design source
- `_reference/korea-design/` is the approved design and the source of truth. Read `HANDOFF.md` first.
- `sections/NN-*.mobile.html` (390 px, primary) and `sections/NN-*.desktop.html` (fluid, max content 1280 px): recreate them faithfully — same copy, order, spacing, assets. Do not redesign. Compare screenshots of the build with the reference files at 390×844 and 1440×900.
- `tokens.json` → CSS variables with the same names in `src/styles.css` (`--paper`, `--ink`, `--lime`, `--space-*`, `--radius-sm`, `--shadow-hard`, `--tilt-*`, …) and Tailwind utilities (`bg-paper`, `text-ink-soft`, `p-space-5`, `rounded-sm`, `shadow-hard`, `font-kr`, `text-h2`, …).
- `css/bundle.css` → `src/pk.css` (pk-* classes, verbatim, in `@layer components`, so utilities override them). `.pk-paper` uses `src/assets/korea/paper-tile.webp` (preloaded in `__root.tsx`), `.pk-spray::before` uses `spray-lime.webp`.
- Reference pages have **no box-sizing reset and default line-height**. To match them: `pk-*` elements except `<button>` are `content-box` (rule at the end of `src/pk.css`; add `box-border` where the reference sets `box-sizing:border-box`), plain elements are border-box (preflight), `<button>` is border-box in browsers anyway, `html` has `line-height: normal`, `.pk-sticker` / `.pk-mark` have `max-width: none` (preflight caps images at 100%; stickers may overhang their box), and the bundle's unclassed bordered boxes (`.pk-list li::before`, `.pk-field input/select`, `.pk-faq summary::after`) are content-box too. Prices: `${PRICE_EUR} €` with a normal space + `whitespace-nowrap` (a no-break space renders 1 px wider at 64 px).
- Fonts are self-hosted subsets in `src/assets/fonts/*-Sub.woff2` (`font-display: swap`), built by `scripts/subset-font.py` (fonttools; dev-only) from the full sources next to them: Kyiv Type Sans (main, Latin + Cyrillic + punctuation incl. `ʼ`, `≈`, `★`, CONT/MIDL pinned, `wght` axis kept whole so metrics match the source exactly; the only preloaded font), Black Han Sans (Korean words), Caveat (marker notes, weight 700), Archivo Black («KOREA '27»; small enough to be inlined into the CSS). The three display faces contain only the characters the prerendered page shows in them: after changing their text run `bun run build && python3 scripts/subset-font.py && bun run build`.
- Assets: `src/assets/korea/` (photos as WebP with the reference base names; Ukrainian `alt` copied from the sections).
- **Images** (as pointcamp-winter): `node scripts/images.mjs` (sharp, dev-only) writes the width variants `src/assets/korea/responsive/<name>-<480|800|1200>w.webp` (clamped to the source width; quality steps down so every file stays ≤ 150 KB) from the sources `src/assets/korea/photo-*.webp` and `src/assets/korea/pointcamp/pc-*.webp`, and re-encodes the decorations (paper tile, lime spray at 600 px, stickers, stamps) from `_reference/korea-design/assets` as WebP. Commit its outputs; re-run it after replacing a photo. It also writes `responsive/dimensions.json` (real size of each photo). Components never import a photo source: `responsive("photo-…")` (`src/lib/responsive.ts`) gives `src`, `srcSet`, `width`, `height`; each `<img>` uses those width/height (never hand-typed: wrong ratios made sections change height when photos loaded, which broke anchor jumps) and sets `sizes` for its measured rendered width. Every `<img>` has width/height; everything below the hero is `loading="lazy" decoding="async"`; the hero hanbok photo is the only `fetchPriority="high"` image.
- Collage budget: torn photos, notes, stickers, stamps only in the hero, program city headers, section dividers and the final CTA. Max one lime area per screen. «KOREA '27» once (final CTA). No motion in the mockup; any added motion must respect `prefers-reduced-motion`.
- Trip data lives only in `src/lib/korea.ts`: dates `TRIP_DATES` «21–30 березня 2027» (Hero tag, About card, Price «Дати:») with `START_ISO` / `END_ISO` for the JSON-LD, the price (3150 €, no «від»), `PARTICIPANT_AGE` «10–20 років» and `MAX_GROUP_SIZE` «15» (number only: About renders «Підлітки й молодь 10–20 років. У групі до 15 учасників.», the Hero subtitle, meta description and JSON-LD read it too), the `[ФОТО]` placeholder, and copy reused by page + meta + JSON-LD: `TRIP_TITLE` (Hero h1 «Весняні канікули в Південній Кореї для підлітків та молоді» = Event name; the hero eyebrow is just «Березень 2027»), `TRIP_SUMMARY`, `PAGE_TITLE`, `PAGE_DESCRIPTION`, `PRICE_EXTRAS` (Price «Оплачується окремо» + Offer description, built from `FLIGHT_FROM_EUR` / `VISA_EUR` / `POCKET_MONEY_EUR` / `DEPARTURE_TRANSFER_EUR`; `ADVANCE_EUR` for the FAQ payment answer), `CITIES` (Event locations). **The page is `noindex, follow` and left out of `sitemap.xml` while `LAUNCHED` is `false` or any `[…]` placeholder remains in the dates/age/size** (`NOINDEX_REASONS` / `SEARCH_INDEXABLE` in `korea.ts`; `scripts/write-seo.mjs` prints the reasons on every build). **Flip `LAUNCHED` to `true` only on launch day**, then rebuild.
- Group photo for WhyUs: add `src/assets/korea/photo-pointcamp-group.webp` (or .jpg/.png) and it replaces the dashed «[ФОТО]» box automatically (`import.meta.glob` in `WhyUs.tsx`).

Partner (copy review pass, 24.11.2026): «Наші партнери», «Ми організовуємо цю подорож разом із Корейсько-українським центром», cards 현지 / 문화 / 팀.
- Header nav: «Питання» → `#faq` is in the mobile menu always, in the desktop row only from xl. The desktop CTA reads «Заявка» from lg to xl (1024–1279 px) and «Залишити заявку» from xl; its `aria-label` is always «Залишити заявку». This keeps the header on one row at every desktop width.
- Code splitting (as pointcamp-winter): every section after the Hero (About, WhyUs, Reviews, WhyKorea, Partner, Route, Program, Price, Faq, FinalCTA, Footer) is a `React.lazy` chunk, each in its own Suspense boundary; still prerendered into the HTML (check: `grep -ac "Lotte World на весь день" dist/client/index.html` ≥ 1). The FAQ data lives in `src/lib/faq.ts` (so the JSON-LD does not pull `Faq.tsx` into the main chunk).
- **Client JS after the first paint**: `scripts/defer-client-js.mjs` runs after `vite build` (part of `bun run build`). It removes the `modulepreload` links from `dist/client/index.html` and replaces the async module script with an inline loader that injects it, together with those modulepreload links (parallel chunk downloads), after the first-contentful-paint entry (or on load, the first pointerdown/keydown/touchstart, or after 3 s). The page is a full prerender, so nothing visible needs JS; this took Lighthouse mobile from LCP 3.7 s to 2.1 s. It fails the build if TanStack's markup changes. Always build with `bun run build`.
- **Pre-hydration safety** (`src/lib/prehydration.ts`): until hydration the page is plain HTML (on Slow 3G that is ~20 s). `PREHYDRATION_GUARD` (inline `<head>` script in `__root.tsx`) holds every form submit and clicks on `[data-replay]` elements that are not `data-ready` yet, queues them on `window.__krQueue` and marks them `data-pending` (busy style in `styles.css`); `useReplayWhenHydrated(ref)` marks the element ready after hydration and replays the action (`requestSubmit()` / `click()`). Used by LeadForm (form) and Header (burger, `data-replay`). Any new JS-only button that matters on first tap needs `data-replay` + the hook. Tested on Slow 3G + 4× CPU: a submit before hydration sends the typed values once hydrated (no native POST, no reload); the first burger tap opens the menu; FAQ `<details>` works natively.
- Anchors: `scroll-padding-top: 80px` on `html` below lg (sticky header 75 px), 0 from lg: every hero/nav/menu/footer link lands 5 px below the header at 390 and at the top at 1440, also on the first jump of a fresh page. `content-visibility: auto` (`.kr-cv`, placeholder `--cv-h`) is only on the Footer: on sections before an anchor target, placeholder heights (real heights vary ±200 px across phone widths) moved the target during the jump.
- `SnapRow`: mobile horizontal scroll-snap row (Reviews below lg, WhyKorea below md). Below its breakpoint it is a focusable region (tabIndex 0, role, aria-label «…, гортайте вбік»); from it a plain grid without those attributes. Prerender ships the mobile attributes; `useMediaQuery` (`src/hooks/use-media-query.ts`, server value given explicitly) drops them after hydration. 22 px top padding with −14 px margin so the Reviews tape is not clipped.
- `PaperStar`: paper-cutout marker-red star (white edge, sticker shadow, fixed tilt), pops in once on scroll via `pk-pop` + `pk-in` (off under reduced motion); decorative, the wrapper carries the text. Used for the five-star rating in Reviews («5 зірок з 5») and inline in Price «Проживання в готелях 3–4★» («3–4 зірки»).
- `PaperDivider` (torn lattice strip + sticker at the top of a section; host section is `relative`, no top border): WhyUs (heart, right), Reviews (smiley, left), Price (star, right).
- `Logo` inlines `src/assets/korea/logo-pointcamp.svg` (`?raw`): purple → `currentColor`, viewBox cropped to the letters (`30 74 515 104`). Header: ink, 24 px / 30 px from lg. Footer: white, 32 px. If the SVG artwork changes, re-check the crop.

## Standard v1 rules (S1–S6, concise)
- **S1 Lead submission** *(done: `LeadForm.tsx` + `src/lib/lead.ts`; tested live with `?test=1` → 200 «Accepted»)*. `src/lib/lead.ts` exports `LANDING = "korea"`, `WEBHOOK_URL` (Make scenario `pointcamp-leads`, `https://hook.eu1.make.com/29wyg57rzqxtajir3fw537ce1vrs2ev2`, public by design), `LeadData { name; phone; email; participant }`, `SendResult { ok; error? }`, `submitLead(data)`. Payload keys exactly: `landing, name, phone, email, participant, page_url, utm_source, utm_medium, utm_campaign, utm_content, utm_term, submitted_at` (ISO), `test` (true when `?test=1`). POST JSON, retry once after 1500 ms, then `{ ok:false, error }`. Push `{ event: "lead_submit" }` to `window.dataLayer` only after a confirmed success; never on failure; guard `window` for SSR. Form via `FormData` with name attrs `name/phone/email/participant`, consent checkbox, CSS-hidden honeypot `website`. Status `idle | submitting | success | error`. On error the filled form is hidden (not unmounted) and an error block shows «Не вдалося надіслати заявку», «Написати в Telegram» (t.me/point_camp, new tab) and «Спробувати ще раз» (back to the filled form). Honeypot hits show success and send nothing. No Telegram tokens or other secrets in client code; the only third-party call is the Make webhook.
- **S2 Analytics.** GTM `GTM-PGJNFD95` is the only tracking loader: `window.dataLayer` is declared by a one-line script in `<head>`, gtm.js is injected by `GTM_LOADER` (start of `<body>`, same as pointcamp-winter) 3 s after `load` or on the first pointerdown/scroll/keydown/touchstart; noscript iframe kept. GA4 `G-2FL7P34KEE` and Meta Pixel `1816738331899667` are tags inside that container; all three IDs are in `src/lib/analytics.ts`. No direct `gtag.js`, no `fbq`/`fbevents`, no second GTM. `window.dataLayer` typed once in `src/vite-env.d.ts`. Allowed custom events: `lead_submit`, `video_play`.
- **S3 Meta & crawl.** `<html lang="uk">`; title `PAGE_TITLE` «Весняні канікули в Кореї для підлітків 2027 | PointCamp»; description `PAGE_DESCRIPTION` (≤160 chars); canonical `https://korea.pointcamp.com.ua/`; robots `noindex, follow` while not `SEARCH_INDEXABLE`; OG (`type=website`, `site_name="Point Camp"` like the Organization name and the other landings (visible copy keeps «PointCamp»), `locale=uk_UA`, url, title, description, image + type/width/height/alt); `twitter:card=summary_large_image` + title/description/image/alt; theme-color `#eae5d8`; favicon. Each meta key once (og:* only in `index.tsx`, not in `__root.tsx`). `public/robots.txt` with explicit Allow for Googlebot, Bingbot, the AI search/assistant bots, the training bots, Twitterbot, facebookexternalhit and `*` + Sitemap. `public/sitemap.xml` and `src/lib/buildDate.generated.ts` (`BUILD_DATE`, Kyiv day; override with `BUILD_DATE=YYYY-MM-DD`) are generated before every build and dev start by `scripts/write-seo.mjs` and gitignored (a fresh clone needs one `bun run build` before `tsc --noEmit`); sitemap `<lastmod>` = build date, empty while noindex. Everything a crawler needs must be in the prerendered HTML as text. JSON-LD is one `@graph` in `src/routes/index.tsx` (`structuredData()`), every value read from `korea.ts` / `FAQ`: Organization (shared `@id` `https://pointcamp.com.ua/#organization`, identical to pointcamp-winter), WebPage (`about` → `#event`, `hasPart` → `#faq`, `publisher` → Organization, `dateModified` = build date), Event (`#event`: name = h1, description = hero lead, 2027-03-21 → 2027-03-30, EventScheduled, OfflineEventAttendanceMode, three Place locations with `addressCountry` KR and English `alternateName`, organizer and performer (both the Organization `@id`), `typicalAgeRange` "10-20" + `audience`, `maximumAttendeeCapacity` 15, image, Offer 3150 EUR InStock `url` `#form` `validFrom` = build date, description listing `PRICE_EXTRAS`), FAQPage (`#faq`, the same 18 questions). ## Commands
- Install: `bun install`
- Clean build: `rm -rf dist && bun run build`
- Serve the build locally: `bunx serve dist/client -p 5000`
- Deploy: `firebase deploy --only hosting:korea` — deploys are done by Dima only.

Cloud sessions: the `korea` environment allows `hook.eu1.make.com` (the default one does not), needed only for live lead tests.

Prerender needs a working Vite preview server; sandbox environments that cannot start one will fail at the prerender step while client and server bundles still compile.

## Conventions
- Work on the default branch `main`. No feature branches, no Firebase preview channels.
- Mobile-first: base styles for 390 px, `md:` (tablet: mobile stacking, centred, max 640 px content), `lg:` (desktop layout from 1024 px).
- Prompts and code comments in English.
- Never write shell commands with `#` comments.
- Assets must be committed to be visible (nothing is fetched at runtime from outside the repo).
- `bun.lock` is the single lockfile; do not add npm/pnpm/yarn lockfiles.
